External Reversi bot instructions

This page describes the external APIs that workshop bots use. These docs are intentionally reachable from external IPs whenever the server itself is started on a network-visible host such as 0.0.0.0.

To expose the docs and bot endpoints on your network, start the server with a public bind address, for example python -m reversi --host 0.0.0.0 --port 8000, then visit {{ server_base_url }}/swagger or {{ server_base_url }}/instructions.

Bot lifecycle

  1. Register exactly once with POST /api/tournament/bots/register.
  2. Store the returned bot_id and secret.
  3. Keep one bot process running and poll GET /api/tournament/bots/<bot_id>/assignment?secret=<secret>.
  4. Make sure every authenticated bot request is at least {{ "%.2f"|format(external_bot_request_interval_seconds) }} seconds after the previous one.
  5. Expect the operator to change that minimum during a tournament and adapt without restarting the bot.
  6. When available becomes true, pick one move from legal_moves.
  7. Submit that move to POST /api/tournament/matches/<game_id>/move.
  8. Repeat until the tournament finishes.

How often to connect

  • Register once when your bot starts.
  • After that, reuse the same base server URL and poll the assignment endpoint repeatedly.
  • The server enforces a hard minimum of {{ "%.2f"|format(external_bot_request_interval_seconds) }} seconds between authenticated requests for the same bot.
  • The operator can change that rate during a tournament from the browser UI, so bots should treat the current limit as dynamic rather than hard-coded.
  • A practical poll interval is about {{ "%.2f"|format(recommended_poll_interval_seconds) }} seconds between assignment checks.
  • That limit is shared across assignment polling and move submission, so a successful poll may need a brief pause before the next move request.
  • The server does not push turns over WebSockets; polling is the expected integration model.

Timeouts and forfeits

  • When a match activates your turn, act quickly.
  • If the current bot-controlled turn stays unresolved for more than {{ bot_turn_timeout_seconds }} seconds, the server records a forfeit.
  • The resulting termination reason is bot_timeout_exceeded.
  • Wrong secrets, out-of-turn submissions, or illegal moves are rejected immediately and do not count as valid moves.
  • If you send requests too quickly, the server replies with 429 Too Many Requests, a Retry-After header, and a JSON retry_after_seconds value.
  • Robust bots should watch the limit_seconds field on successful responses and always honor Retry-After after a 429 so they do not overload the server after a live rate change.

Register a bot

Send a unique bot name to the registration endpoint:

{
  "name": "alpha"
}

Example request:

POST {{ server_base_url }}/api/tournament/bots/register
Content-Type: application/json

Example response:

{
  "bot_id": "2bca0f14",
  "name": "alpha",
  "secret": "generated-secret",
  "created_at": "2026-09-25T12:00:00+00:00",
  "last_seen_at": "2026-09-25T12:00:00+00:00",
  "status": "connected",
  "managed": false,
  "process_alive": false,
  "pid": null
}

If another bot already uses the same name, registration is rejected.

Field reference

Field Meaning
board 8x8 array. . means empty, B black, W white.
current_player Whose turn it is right now: B or W.
legal_moves All legal moves for the current player. Your submitted move must come from this list.
scores Current piece counts: black and white.
history Ordered list of past moves, passes, or forfeits.
metadata Tournament-specific data including bot ids, names, and match index.

Submit a move

Send one legal move back to the match endpoint:

{
  "bot_id": "2bca0f14",
  "secret": "generated-secret",
  "row": 2,
  "col": 3
}

The row and col values are zero-based indexes.
